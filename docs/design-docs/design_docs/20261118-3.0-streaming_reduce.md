# Streaming Reduce on Milvus 3.0

This ports Query and Search streaming from
[PR #55219](https://github.com/milvus-io/milvus/pull/55219) to 3.0's shard
delegator. Workers execute their existing segment pipelines and split the
completed results into Chunks. The delegator still owns the shard snapshot
and reduces the worker results before returning its vchannel result.

```text
Worker QNs -- SearchSegmentsStream --> shard leader -- SearchStream --> Proxy
Worker QNs -- QueryReduceStream -----> shard leader -- QueryReduceStream -> Proxy
                     worker mode                           leader mode
```

Workers split their completed results. For plain PK-ordered Query and ordinary
ungrouped ANN Search, the delegator does not build a completed vchannel result:
its reducer waits for a head or EOF from each worker, merges enough rows or hits
for one Chunk, and sends it while the shard snapshot is still pinned. The next
receive resumes from the same worker cursors. Proxy repeats the merge across
vchannels and stops pulling when the requested window is full, or at EOF for
unlimited Query. The SDK response remains unary.

Request-level cost and snapshot metadata travel once. Ungrouped Search merges
query-major Chunks in the existing score and PK order, with shard-local
deduplication and Proxy pagination. Ordinary Query merges PK-ordered rows,
selects the latest version within each vchannel, and rejects duplicate PKs
across vchannels. Requery and the unordered delete scan are unchanged.

For plain Query ORDER BY, the delegator keeps a row reference for the newest
version of each PK as worker Chunks arrive. Only at worker EOF does it rank
those rows and emit its offset + limit window in Chunks. A winning reference
keeps its source Chunk alive. Proxy merges vchannel heads in ORDER BY order
with PK as the tie-breaker. It drains past the requested window to detect
cross-vchannel duplicate PKs, not to add rows to the response.

As in [PR #55861](https://github.com/milvus-io/milvus/pull/55861), Batch and ReduceStream
use the same group key order before they apply a GROUP BY limit. Without ORDER BY, the keys follow declaration order,
ascending, with NULLs last. With ORDER BY, the remaining group keys break ties.
Each worker sends one row per key. The delegator and Proxy merge all heads
with the least key, then emit that group. Neither needs the next Chunk to
finish the current group. The internal limit includes the offset; Proxy
applies the offset once. Each stream holds one input Chunk per child.

Global aggregates have no group key. Each reducer merges each incoming Chunk
into one running partial and returns it only after every child reaches EOF.
AVG carries SUM and COUNT until Proxy computes the final value.

For ordinary grouped Search and Search aggregation, each hop tracks the
accepted group keys and hit counts per query vector across Chunks. It admits
up to the internal topK groups and group_size hits per group. A delegator can
send its first Chunk before worker EOF. Proxy retains the candidate window,
including groups before the offset. Its existing pipeline applies the offset
once, orders the grouped output, or computes the aggregation buckets.

Hybrid Search uses one RPC and one pinned snapshot per vchannel. Each
sub-search merges its workers independently. The delegator sends each Chunk
with its request index, then sends an end marker for that index, even for
zero hits. Only the gRPC send is serialized. The shared snapshot stays pinned
until all sub-searches finish or cancellation joins their workers.

Proxy reads each RPC in wire order and routes Chunks by index. If A is
waiting for another vchannel, its queued Chunks must not stop that reader
from reaching B. Each queue can retain up to NQ times that sub-search's
topK hits from one vchannel, multiplied by group size for grouped Hybrid.
This is a hit limit, not a byte limit. Reading
or closing the logical stream releases its queued hits. Closing one logical
stream does not close the shared RPC. Fusion waits for all candidate windows
and for physical EOF, so a trailing error cannot produce a partial success.
Older leaders have no end marker: physical EOF finishes all their indexes.
For grouped Hybrid, the delegator applies the local group limits as it merges
worker hits by score. For each vector, Proxy takes all the hits from each
vchannel in Batch input order. It does not sort by score, deduplicate across
vchannels, or apply the group limits again. Fusion still needs all those hits.

Proxy reads the first Chunk inside the existing per-channel leader retry
callback. If retries fail, the request attempt cancels sibling opens. A
successful open remains live until reduction closes it. A later receive
failure returns an error rather than replaying one leader into a partial merge.
A worker setup failure cancels sibling opens inside the delegator. A failed
Hybrid sub-search also cancels its sibling sub-searches on that vchannel.
An older worker or leader reporting gRPC `Unimplemented` falls back to its
unary RPC before any Chunk is accepted. For grouped Query, that fallback
names the group keys explicitly so an older unary peer sorts before limiting.
Keep ReduceStream off when mixing builds of this port that disagree on the
group order: an older streaming peer can return an already truncated window.

The server settings `proxy.enableReduceStream` (default `false`) and
`proxy.reduceStreamChunkBytes` (default `262144`) are refreshable, captured
once per task for its leader retries, and not SDK-overridable.
Search with partial results enabled stays on Batch. Two-stage Search keeps
the filter-only pass unary; only the candidate pass may stream. QueryScan
is outside this port.
