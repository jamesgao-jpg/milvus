# Streaming Reduce on Milvus 3.0

This first slice ports plain ANN Search from [PR #55219](https://github.com/milvus-io/milvus/pull/55219)
to 3.0's shard delegator. Only the leader-to-Proxy result path changes.
Workers still return unary Search results and the delegator still completes
its Batch reduction before sending the first Chunk.

```text
Worker QNs -- unary Batch --> shard leader -- SearchStream Chunks --+
Worker QNs -- unary Batch --> shard leader -- SearchStream Chunks --+
                                                                  v
                                        Proxy OrderedReduceStream (topK per vector)
                                                                  |
                                                                  v
                                        Existing Search post-processing
```

The leader splits along query-major hit order using the reducible-payload byte
threshold. One hit is indivisible. Only the first Chunk carries leader cost,
MVCC, and search-count metadata. Proxy buffers one Chunk per leader, merges
in Batch score and PK order, and stops pulling when it can finalize the
last vector. As in 3.0 Batch, duplicate PKs across leaders are not removed.
The existing pipeline sees one merged result and keeps score conversion,
field organization, and requery.

Proxy reads the first Chunk inside the existing per-channel leader retry
callback. If retries fail, the request attempt cancels sibling opens. A
successful open remains live until reduction closes it. A later receive
failure returns an error rather than replaying one leader into a partial merge.
An older leader reporting gRPC `Unimplemented` is served through its unary
RPC before any Chunk is accepted.

The server settings `proxy.enableReduceStream` (default `false`) and
`proxy.reduceStreamChunkBytes` (default `262144`) are refreshable, captured
once per Search task for its leader retries, and not SDK-overridable.
Hybrid, grouping, reranking,
offset, ORDER BY, range Search, and iterators stay on Batch. Query, including
the existing streaming delete scan, is unchanged.
